โมดูล 0: เริ่มต้นใช้งาน SimpleHAL

ระดับเริ่มต้น
สิ่งที่ต้องรู้: ทุกโปรเจกต์ CH32V003 ต้องมี 3 ขั้นตอนบังคับก่อนเรียกใช้ API ใด ๆ — อ่านให้ครบก่อนเขียนโค้ด

ภาพรวม

ก่อนเรียกใช้ฟังก์ชันใด ๆ ใน SimpleHAL ทุกโปรเจกต์ต้องมี 3 สิ่งนี้เสมอ:

  1. #define CH32V003_PACKAGE — เลือกแพ็กเกจให้ตรงกับชิปที่ใช้งาน
  2. SystemCoreClockUpdate() — ต้องเป็นบรรทัดแรกใน main()
  3. Timer_Init() — ต้องเรียกหลัง SystemCoreClockUpdate()

ถ้าขาดข้อใดข้อหนึ่ง โค้ดอาจคอมไพล์ผ่านแต่ไม่ทำงาน หรือทำงานผิดพลาด

flowchart TD
    A["#define CH32V003_PACKAGE"] --> B["SystemCoreClockUpdate()"]
    B --> C["Timer_Init()"]
    C --> D["เรียกใช้ API อื่น ๆ ได้"]

ขั้นที่ 1: เลือกแพ็กเกจ

กำหนด #define CH32V003_PACKAGE ก่อน #include "SimpleHAL.h" เพื่อให้ไลบรารีรู้ว่าชิปมีกี่ขาและขาไหนใช้ได้บ้าง

#define CH32V003_PACKAGE PACKAGE_TSSOP20
#include "SimpleHAL.h"

แพ็กเกจที่รองรับ

แพ็กเกจขาที่ใช้ได้ชิป
PACKAGE_SOP86 pinsCH32V003J4M6
PACKAGE_SOP1614+ pinsCH32V003F4P6
PACKAGE_TSSOP2018 pinsCH32V003F4U6
PACKAGE_QFN2018 pinsCH32V003F4K6
ถ้าลืม: SimpleHAL.h จะ default เป็น TSSOP20 และแสดงคำเตือนตอนคอมไพล์ — แต่โค้ดอาจทำงานผิดถ้าชิปจริงเป็น SOP8

ขั้นที่ 2: SystemCoreClockUpdate()

ต้องเป็นบรรทัดแรกใน main() — อัปเดตตัวแปร SystemCoreClock ให้ถูกต้องตามความถี่จริงของ HSI (48MHz default)

int main(void)
{
    SystemCoreClockUpdate();  // ต้องเป็นบรรทัดแรก
    // ...
}

ฟังก์ชันนี้เป็นส่วนหนึ่งของ CMSIS — ถูกใช้ภายในโดย Delay_Ms(), Delay_Us(), USART_Printf_Init() และโมดูลอื่น ๆ อีกมาก

ถ้าลืม: Delay_Ms() จะหน่วงเวลาไม่ถูกต้อง (อาจช้าหรือเร็วผิด), USART_Printf_Init() จะคำนวณ baud rate ผิด — ทำให้สื่อสาร Serial ไม่ได้

ขั้นที่ 3: Timer_Init()

ต้องเรียกหลัง SystemCoreClockUpdate() — ตั้งค่า SysTick ให้ทำงานที่ 1ms resolution

int main(void)
{
    SystemCoreClockUpdate();
    Timer_Init();  // ต้องเรียกก่อนใช้ Delay
    // ...
}

Timer_Init() จำเป็นสำหรับฟังก์ชันที่ต้องใช้เวลาอ้างอิง: Delay_Ms(), Get_CurrentMs(), Non-Blocking Timer

ถ้าลืม: Delay_Ms() และ Get_CurrentMs() จะไม่ทำงาน — โปรแกรมอาจค้างใน infinite loop ถ้าใช้ Delay แบบรอ SysTick

Timer Resource Map

CH32V003 มี 2 Timer ทั้งหมด — Timer_Init() ใช้ SysTick (ไม่นับรวม):

Timerใช้โดยข้อจำกัด
SysTickTimer_Init() → Delay_Ms(), Get_CurrentMs()ใช้ได้เฉพาะ 1ms resolution, ไม่สามารถใช้ร่วมกับฟังก์ชันอื่น
TIM1 (16-bit Advanced)SimplePWM หรือ SimpleTIMใช้ได้อย่างใดอย่างหนึ่งเท่านั้น — โมดูลที่เรียก *_Init() ก่อนจะ "จอง" (owner) ไว้ อีกโมดูลเรียกตามจะ error
TIM2 (16-bit General)SimplePWM (PWM2) หรือ SimpleTIM หรือ SimpleTIM_Ext (Stopwatch/Countdown)ใช้ได้อย่างใดอย่างหนึ่งเท่านั้นจาก 3 โมดูลนี้ — กลไก ownership เดียวกับ TIM1
กลไก Ownership (Silent Fail): ตัวแปรภายใน g_tim1_owner / g_tim2_owner (ค่า TIM_OWNER_NONE / TIM_OWNER_PWM / TIM_OWNER_TIMER / TIM_OWNER_TIMEXT) จะถูกตั้งเมื่อโมดูลแรกเรียก Init สำเร็จ — โมดูลอื่นที่พยายามเรียก Init ตามบน Timer เดียวกันจะถูกปฏิเสธแบบเงียบ (PWM_Init(), TIM_SimpleInit(), TIM_AttachInterrupt() ฯลฯ ล้วนเป็น void — ไม่มี return value ให้เช็คเลย ถ้าชนกัน ฟังก์ชันจะ return ออกไปเฉยๆ โดย timer ยังเป็นของเจ้าของเดิม ไม่มีการแจ้งเตือนใดๆ) วิธีเดียวที่ตรวจสอบได้คือดูว่า PWM/Timer ตัวที่เรียกทีหลังทำงานจริงหรือไม่ (เช่น วัดสัญญาณจริงหรือดู duty ที่ได้)

ตารางสรุปความขัดแย้งของทรัพยากร (Resource Conflict Map)

นอกจาก Timer แล้ว ยังมีทรัพยากรอื่นที่ใช้ร่วมกันไม่ได้ระหว่างโมดูล — สรุปรวมจากทุกโมดูลไว้ที่นี่เพื่อวางแผนก่อนเขียนโค้ดที่ใช้หลายโมดูลพร้อมกัน:

ทรัพยากรใช้โดยข้อจำกัด
TIM1_UP IRQSimplePWM (TIM1) / SimpleTIM (TIM1 interrupt mode)1 handler ต่อ MCU — ผูกกับ TIM1 ownership ด้านบน
TIM2 IRQSimplePWM (TIM2/PWM2) / SimpleTIM / SimpleTIM_Ext1 handler ต่อ MCU — ผูกกับ TIM2 ownership ด้านบน
USART1 IRQSimpleUSART (RX ring buffer)ถ้ามีไลบรารีอื่นที่ตั้ง USART1_IRQHandler เองจะ conflict ตอน link — ใช้ USART_RxByteHook() แทนการเขียน handler เองเสมอ
EXTI Line 0-7SimpleGPIO — attachInterrupt()ผูกตามเลขขา ไม่ใช่ port — PC1 และ PD1 ใช้ EXTI Line 1 ร่วมกัน เรียก attachInterrupt พร้อมกันบน 2 ขาที่เลขท้ายซ้ำกันไม่ได้ (ดูรายละเอียดที่ SimpleGPIO)
DMA1 Channel 1-7SimpleDMA — ADC / USART / SPI / I2C / TIM ล้วนขอ channel ผ่าน DMA_Channel ที่ผู้ใช้ระบุเองแต่ละ channel มี IRQ handler แยกกัน (DMA1_Channel1_IRQHandler ... Channel7) — ต้องเลือก channel ไม่ให้ซ้ำกันเองระหว่างการใช้งานพร้อมกันหลายชุด (ดูตัวอย่างที่ SimpleDMA)
WWDG IRQSimpleWWDGผู้ใช้ต้องประกาศ WWDG_IRQHandler() เองแล้วเรียก WWDG_IRQHandler_Callback() ข้างใน — ถ้ามีไลบรารีอื่นประกาศ WWDG_IRQHandler ซ้ำจะ link error
วิธีอ่านตาราง: ถ้าโปรเจกต์ใช้หลายโมดูลพร้อมกัน (เช่น PWM + Stopwatch + Interrupt Button) ให้ไล่เช็คว่าแต่ละโมดูลใช้ทรัพยากรแถวไหนทับกันหรือไม่ก่อนเขียนโค้ดจริง

ตัวอย่างขั้นต่ำ — Hello World

โค้ดสมบูรณ์ที่รวม LED กระพริบ + USART Debug Print:

#define CH32V003_PACKAGE PACKAGE_TSSOP20
#include "SimpleHAL.h"

int main(void)
{
    SystemCoreClockUpdate();
    Timer_Init();

    // LED
    pinMode(PC0, PIN_MODE_OUTPUT);

    // USART Debug
    USART_Printf_Init(USART1, BAUD_115200);
    printf("\r\nSimpleHAL Ready\r\n");

    while(1)
    {
        digitalWrite(PC0, HIGH);
        Delay_Ms(500);
        digitalWrite(PC0, LOW);
        Delay_Ms(500);
        printf("Tick\r\n");
    }
}

วิธีการ Include

SimpleHAL รองรับการ include 2 แบบ:

แบบที่ 1: Single Include (แนะนำ)

#define CH32V003_PACKAGE PACKAGE_TSSOP20
#include "SimpleHAL.h"   // รวมทุกโมดูล — ง่ายสุด

ข้อดี: สะดวก ไม่ต้อง include หลายไฟล์ — เหมาะสำหรับโปรเจกต์ทั่วไป

แบบที่ 2: Selective Include

#define CH32V003_PACKAGE PACKAGE_TSSOP20
#include "SimpleDelay.h"  // เฉพาะ Delay
#include "SimpleGPIO.h"   // เฉพาะ GPIO

ข้อดี: ลดขนาดโค้ดและเวลา compile — เหมาะสำหรับโปรเจกต์ที่ต้องการควบคุม unit ทุกตัว

แนะนำ: ใช้ Single Include (SimpleHAL.h) ในช่วงพัฒนา — เปลี่ยนเป็น Selective Include เมื่อโปรเจกต์เสร็จและต้องการ optimize ขนาด binary

วิธี Debug เมื่อโค้ดไม่ทำงานตามคาด

เมื่อเจอปัญหาแล้วไล่ตาม "ปัญหาที่พบบ่อย" ในแต่ละหน้าโมดูลแล้วยังไม่เจอ ให้ไล่ตามลำดับนี้:

1. ตรวจ 3 ขั้นตอนบังคับก่อนเสมอ

ปัญหาแปลกๆ จำนวนมาก (baud rate ผิด, delay ผิดเวลา, timer ไม่เดิน) มีสาเหตุจากลืม SystemCoreClockUpdate() หรือ Timer_Init() — กลับไปเช็คส่วน "3 ขั้นตอนบังคับ" ด้านบนก่อนเสมอเป็นอันดับแรก

2. ยืนยันด้วย USART Debug Print

วิธีเร็วที่สุดในการดูว่าโค้ดเดินถึงจุดไหน — ใช้ USART_Printf_Init() + printf() (หรือ USART_Print()) แทรกใน flow เพื่อยืนยันว่าค่าที่อ่านได้/return value ของแต่ละฟังก์ชันตรงกับที่คาดไว้ ก่อนสงสัยว่าเป็นปัญหาฮาร์ดแวร์

3. ใช้ Logic Analyzer / Oscilloscope สำหรับโปรโตคอลสื่อสาร

เมื่อ USART debug print ยืนยันว่าโค้ดเดินถูก แต่อุปกรณ์ภายนอกไม่ตอบสนอง (I2C, SPI, 1-Wire) ให้จับสัญญาณจริงเปรียบเทียบกับ timing ที่ระบุไว้ในเอกสารของแต่ละโมดูล:

โปรโตคอลสิ่งที่ต้องดูอ้างอิง timing
I2C (Hardware/Soft)Start/Stop condition, ACK bit ต่อ byte, ความเร็ว SCL ตรงกับที่ตั้งหรือไม่SimpleI2C — ใช้ ignore_ack=1 ใน I2C_Soft_Write เพื่อจับสัญญาณโดยไม่ต้องรออุปกรณ์ตอบ ACK จริง
1-Wireความกว้าง Reset pulse / Presence pulse / Time slot ตรงช่วงที่กำหนดหรือไม่Simple1Wire — ตาราง Timing Constants (Standard vs Overdrive)
SPIClock polarity/phase (CPOL/CPHA) ตรงกับอุปกรณ์ปลายทาง, CS timingSimpleSPI
USARTBaud rate ตรงกันทั้งสองฝั่ง, framing (start/stop bit), ground ร่วมกันSimpleUSART

4. เช็คทรัพยากรที่ใช้ร่วมกันชนกันหรือไม่

ถ้าโมดูลหนึ่งเคยทำงานได้แต่พอเพิ่มอีกโมดูลแล้วเสีย (เช่น เพิ่ม Stopwatch แล้ว PWM หยุดทำงาน) มักเกิดจาก Timer/IRQ/EXTI Line ชนกัน — ไล่เช็คตาม ตารางสรุปความขัดแย้งของทรัพยากร ด้านบน

ลำดับที่แนะนำ: Software (ค่า/return value ผ่าน printf) → Timing (logic analyzer) → Resource conflict (ตาราง) — ไล่จากที่ตรวจง่ายสุดไปหายากสุดเสมอ ไม่ต้องเปิด oscilloscope ถ้ายังไม่ยืนยันด้วย printf ก่อน

เช็กลิสต์ก่อนเขียนโค้ด

  1. เลือกแพ็กเกจถูกต้องหรือไม่ (SOP8 / SOP16 / TSSOP20 / QFN20)
  2. SystemCoreClockUpdate() อยู่บรรทัดแรกใน main()
  3. Timer_Init() อยู่หลัง SystemCoreClockUpdate() ก่อนใช้ Delay_Ms()
  4. ตรวจสอบว่า pin ที่ใช้มีอยู่ในแพ็กเกจที่เลือก
  5. กรณีใช้ SOP8: ระวัง PC0 ไม่มี — ใช้ PA1, PC1, PC2, PC4, PD6 แทน
