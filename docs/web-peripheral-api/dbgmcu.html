DBGMCU — ระบุตัวตนชิปและควบคุมพฤติกรรมดีบัก

ระดับสูง
ไลบรารี: #include <ch32v00x_dbgmcu.h> — นี่คือ Standard Peripheral Library (SPL) ระดับล่าง ใช้สำหรับอ่านรหัสระบุชิป (Chip ID / Device ID / Revision ID) และควบคุมว่าเพอริเฟอรัลบางตัวควรหยุดทำงานหรือไม่เมื่อ core ถูกหยุดโดย debugger
DBGMCU ไม่มี wrapper ใน SimpleHAL เพราะเป็นฟังก์ชันสำหรับงาน debug/introspection โดยเฉพาะ (เช่น พิมพ์รุ่นชิปออก UART ตอน boot, ตรวจสอบรุ่นก่อนใช้ feature เฉพาะรุ่น) ไม่ใช่ peripheral ที่ใช้ในโค้ด production ทั่วไป — เรียกใช้ฟังก์ชันในหน้านี้โดยตรงได้เลย

ผังการใช้งานทั่วไป

ค่าคงที่หลัก (#define) — CFGR0 / DEBUG Control Register

ใช้กับ DBGMCU_Config() เพื่อกำหนดว่าเพอริเฟอรัลใดจะหยุดทำงานตามไปด้วยเมื่อ core ถูกหยุด (halt) โดย debugger — มีประโยชน์เวลา single-step เพื่อไม่ให้ watchdog หรือ timer นับต่อจนรีเซ็ตขณะ breakpoint ค้าง

ค่าคงที่ความหมาย
DBGMCU_IWDG_STOPหยุด IWDG (Independent Watchdog) เมื่อ core หยุด
DBGMCU_WWDG_STOPหยุด WWDG (Window Watchdog) เมื่อ core หยุด
DBGMCU_TIM1_STOPหยุดตัวนับ TIM1 เมื่อ core หยุด
DBGMCU_TIM2_STOPหยุดตัวนับ TIM2 เมื่อ core หยุด
ค่าเหล่านี้ใช้แบบ OR รวมกันได้ เช่น DBGMCU_Config(DBGMCU_IWDG_STOP | DBGMCU_WWDG_STOP, ENABLE) เพื่อหยุดทั้งสอง watchdog พร้อมกันตอนดีบัก

ตารางอ้างอิงฟังก์ชัน

ฟังก์ชันพารามิเตอร์คืนค่าคำอธิบาย
DBGMCU_GetCHIPID(void) — uint32_t อ่านรหัสระบุชิปแบบเต็ม (32-bit) จาก address 0x1FFFF7C4 — ใช้แยกรุ่น/แพ็กเกจของ CH32V003 ได้ เช่น 0x003005x0 = CH32V003F4P6, 0x003105x0 = CH32V003F4U6, 0x003205x0 = CH32V003A4M6, 0x003305x0 = CH32V003J4M6
DBGMCU_GetDEVID(void) — uint32_t อ่านเฉพาะส่วน Device ID (16 บิตล่างของ Chip ID เดียวกัน — มาสก์ด้วย 0x0000FFFF)
DBGMCU_GetREVID(void) — uint32_t อ่านเฉพาะส่วน Revision ID (16 บิตบนของค่าเดียวกัน — shift ขวา 16 บิต)
__get_DEBUG_CR(void) — uint32_t อ่านค่า DEBUG Control Register ปัจจุบันโดยตรงผ่าน CSR instruction (csrr จาก CSR 0x7C0) — ใช้ภายใน DBGMCU_Config() เมื่อต้องอ่านค่าก่อนแก้บางบิต
__set_DEBUG_CR(value) value: ค่า 32-bit ที่จะเขียนทับทั้ง register void เขียนค่าลง DEBUG Control Register โดยตรงผ่าน CSR instruction (csrw) — เขียนทับทั้ง register ไม่ใช่ set/clear เฉพาะบิต
DBGMCU_Config(DBGMCU_Periph, NewState) DBGMCU_Periph: OR ของ DBGMCU_*_STOP
NewState: ENABLE/DISABLE		 void เปิด/ปิดพฤติกรรม "หยุดเพอริเฟอรัลเมื่อดีบัก" — ตอน ENABLE จะเขียนทับค่าใหม่ทั้ง register ด้วย __set_DEBUG_CR ตรงๆ; ตอน DISABLE จะอ่านค่าเดิมด้วย __get_DEBUG_CR ก่อนแล้วเคลียร์เฉพาะบิตที่ระบุ
ข้อควรระวังของ DBGMCU_Config(..., ENABLE): เส้นทาง ENABLE เขียนทับทั้ง registerด้วยค่าพารามิเตอร์ที่ส่งเข้าไปตรงๆ (ไม่ได้ OR กับค่าที่มีอยู่เดิมเหมือนเส้นทาง DISABLE) — ถ้าเคยตั้งค่าอื่นไว้ก่อนหน้าแล้วเรียก ENABLE ซ้ำด้วยค่าพารามิเตอร์ใหม่ จะทำให้บิตที่ตั้งไว้ก่อนหน้าหายไปโดยไม่ตั้งใจ ถ้าต้องการเพิ่มบิตใหม่โดยคงบิตเดิมไว้ ให้ OR ค่าที่อ่านจาก __get_DEBUG_CR() เข้ากับบิตใหม่เองก่อนส่งเข้า DBGMCU_Config

กลุ่มฟังก์ชันที่ใช้ร่วมกัน

1. อ่าน Chip ID เต็มรูปแบบตอน boot

#include <ch32v00x.h>

uint32_t chip_id = DBGMCU_GetCHIPID();

// เทียบกับรุ่นที่รู้จัก
switch (chip_id & 0xFFFFFF00) {
    case 0x00300500: /* CH32V003F4P6 */ break;
    case 0x00310500: /* CH32V003F4U6 */ break;
    case 0x00320500: /* CH32V003A4M6 */ break;
    case 0x00330500: /* CH32V003J4M6 */ break;
    default: /* รุ่นที่ไม่รู้จัก */ break;
}

ใช้ DBGMCU_GetCHIPID() เพื่อดึงรหัสชิปแบบเต็ม แล้วเทียบ bit pattern เพื่อระบุแพ็กเกจ/รุ่นที่ใช้งานจริง

2. แยก Device ID และ Revision ID

uint32_t dev_id = DBGMCU_GetDEVID();   // 16 บิตล่าง
uint32_t rev_id = DBGMCU_GetREVID();   // 16 บิตบน

// ตัวอย่างพิมพ์ผ่าน USART (สมมติมีฟังก์ชัน USART_Printf)
USART_Printf("Device ID: 0x%04X, Revision: 0x%04X\r\n", dev_id, rev_id);

ใช้เมื่อสนใจแยกเฉพาะ Device ID หรือ Revision ID โดยไม่ต้องเอามาแยกบิตเอง

3. หยุด Watchdog ระหว่างดีบัก (ป้องกันรีเซ็ตขณะ breakpoint)

// หยุดทั้ง IWDG และ WWDG เมื่อ core ถูกหยุดโดย debugger
DBGMCU_Config(DBGMCU_IWDG_STOP | DBGMCU_WWDG_STOP, ENABLE);

// ภายหลังถ้าต้องการเพิ่ม TIM1 โดยไม่ทำลายบิตเดิม ต้องอ่านค่าปัจจุบันมา OR เอง
uint32_t cur = __get_DEBUG_CR();
__set_DEBUG_CR(cur | DBGMCU_TIM1_STOP);

ป้องกัน watchdog รีเซ็ต MCU ขณะหยุด single-step อยู่นาน ๆ ใน debugger — ปิดกลับก่อน flash รุ่น production จริงเพื่อให้ watchdog ทำงานตามปกติ

ปัญหาที่พบบ่อย

ปัญหาสาเหตุวิธีแก้
เทียบค่า Chip ID แล้วไม่ตรงกับที่คาดไว้เลยสักรุ่น เทียบ DBGMCU_GetCHIPID() แบบเต็ม 32-bit ตรงๆ ทั้งที่ค่าจริงมีส่วนท้าย (lot/wafer marking) ที่เปลี่ยนได้ในแต่ละล็อตการผลิต — เอกสารเขียนไว้เป็น 0x003005x0 ที่ x เป็นค่าที่แปรผันได้ มาสก์เฉพาะบิตที่ใช้แยกรุ่นจริง (เช่น chip_id & 0xFFFFFF00) ก่อนเทียบ อย่าเทียบทั้ง 32-bit ตรงๆ
เรียก DBGMCU_Config(..., ENABLE) ครั้งที่สองแล้วการตั้งค่าก่อนหน้าหายไป เส้นทาง ENABLE ของ DBGMCU_Config เขียนทับทั้ง register ด้วยค่าพารามิเตอร์ที่ส่งเข้าไป ไม่ได้ OR กับค่าเดิมเหมือนเส้นทาง DISABLE ถ้าต้องการเพิ่มบิตใหม่โดยคงบิตเดิม ให้ OR ค่าเดิมจาก __get_DEBUG_CR() เข้ากับบิตใหม่เอง แล้วส่งผลรวมเข้า DBGMCU_Config หรือเรียก __set_DEBUG_CR() ตรงๆ
ตั้งค่า DBGMCU_Config(DBGMCU_IWDG_STOP, ENABLE) ไว้ในโค้ด production แล้วลืมปิด ค่านี้มีผลเฉพาะตอน core ถูก debugger หยุด (halt) เท่านั้น — ไม่กระทบการทำงานปกติเมื่อรันอิสระ (free-run) จึงมักถูกลืมทิ้งไว้ในโค้ดจริงโดยไม่มีผลเสียทันที ไม่จำเป็นต้องนำออกเพราะไม่กระทบการทำงานตอน free-run แต่ควรตระหนักว่าเวลา debug ด้วย breakpoint watchdog จะไม่นับต่อ ทำให้พฤติกรรม watchdog ตอน debug กับตอนใช้งานจริงต่างกัน
ใช้ __get_DEBUG_CR()/__set_DEBUG_CR() แล้ว build ไม่ผ่านหรือพฤติกรรมแปลก ฟังก์ชันทั้งสองนี้เข้าถึง CSR (Control and Status Register) เฉพาะของแกน RISC-V ผ่าน inline assembly (csrr/csrw ที่ CSR 0x7C0) โดยตรง — เป็นรีจิสเตอร์ระดับ debug ที่ไม่ใช่ memory-mapped ปกติ เรียกผ่าน DBGMCU_Config() แทนถ้าแค่ต้องการเปิด/ปิดการหยุดเพอริเฟอรัล ใช้ __get_DEBUG_CR/__set_DEBUG_CR ตรงๆ เฉพาะกรณีต้องการควบคุมบิตอื่นที่ DBGMCU_Config ไม่รองรับเท่านั้น
